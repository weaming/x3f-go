# x3f-go 项目技术文档

本文档综合了 `docs` 目录下的所有 Markdown 文件，旨在提供关于 X3F 文件格式、处理流程、色彩科学以及 `x3f-go` 项目中关键技术实现的详细概述。

## 1. X3F 格式与处理总览

### 1.1. Foveon X3 传感器与 X3F 格式

- **三层传感器结构**: Foveon X3 传感器通过在硅的不同深度吸收不同波长的光来分离颜色，每个像素位置都能记录完整的 RGB 信息。
  - **顶层**: 捕获蓝光 (B)
  - **中层**: 捕获绿光 (G)
  - **底层**: 捕获红光 (R)
- **优势**: 无需“去马赛克”(demosaicing)，理论上能提供更锐利的细节和无插值伪影的色彩。
- **劣势**: 高 ISO 噪声大，动态范围相对较小，且原始数据需要复杂的色彩校正。
- **X3F 文件**: 一种完全独立的私有 RAW 格式，其内部结构和数据编码随相机世代更迭而变化。

### 1.2. X3F 文件结构

X3F 采用“目录置于末尾”的 I/O 模型，便于写入。

- **文件头 (`File Header`)**: 以 "FOVb" 签名开头，包含版本号和指向目录段的指针。
- **目录段 (`Directory Section`)**: 位于文件末尾，是文件内容的“藏宝图”，包含多个条目，每个条目指向一个具体的数据段。
- **数据段 (`Data Sections`)**:
  - `IMAG`: 核心图像数据（三层 Foveon 数据），根据相机型号有不同压缩方式。
  - `IMA2`: 预览图或缩略图。
  - `PROP`: 属性数据，如相机设置、拍摄参数，以 Sigma 自定义的键值对格式存储。
  - `CAMF`: 相机特定的格式信息，通常包含**加密的**校准数据，如色彩矩阵、白平衡增益等。

### 1.3. 科学的 X3F 处理流程

一个完整的、能产生准确色彩的 X3F 处理管线如下：

```
📷 X3F 文件
    ↓
【1】读取并解码/解密三层 RAW 数据
    ↓
【2】传感器校正 (暗场减法 / 热像素修复)
    ↓
【3】线性化 (校正 Foveon 特有的非线性响应)
    ↓
【4】色彩校正 (应用色彩校正矩阵，RAW → XYZ)
    ↓
【5】白平衡 (在线性 RGB 空间应用增益)
    ↓
【6】去噪 (例如使用 Non-Local Means 或 Bilateral Filter)
    ↓
【7] 转换到工作色彩空间 (如 ACES, sRGB)
    ↓
【8】曝光/对比度调整
    ↓
【9】色调映射 (Tone Mapping，动态范围压缩)
    ↓
【10】锐化 (可选，Foveon 本身很锐利)
    ↓
【11】转换到输出色彩空间并应用 Gamma 校正
    ↓
【12】输出 (JPEG, DNG, TIFF)
```

## 2. X3F 解码、开源生态与陷阱

### 2.1. 开源社区的困境

Foveon X3F 格式的处理在开源社区一直是个难题。

- **`dcraw`**: 最早的开源 RAW 处理工具，但对 Foveon 的支持效果不佳，色彩分离不准。
- **`LibRaw`**: 作为 `dcraw` 的继承者，选择将 Foveon 支持“外包”给一个名为 `Kalpanika/x3f-tools` 的外部 C 库。
- **`Kalpanika/x3f-tools`**: 一个由社区爱好者逆向工程 X3F 格式的项目。然而，该项目对 Quattro (v4.x) 格式的支持是**“不完整的”**，并且自 2017 年以来已停止更新。其开发者承认无法解密 `CAMF` 中的所有元数据。
- **现状**: 由于这种破碎的依赖关系，大多数现代开源软件（如 Darktable）要么不支持 X3F，要么支持不佳。`LibRaw` 的官方支持列表已将 Quattro 系列相机标记为 **"DNG only"**。

### 2.2. 不同世代 X3F 的解析差异

解析 X3F 的主要挑战在于其内部数据格式随相机世代更迭而变化。一个合格的解析器必须能够“分支”其逻辑。

| 特性                    | Classic (SD9/10/14) | Merrill (SD1M/DPxM) | Quattro (sdQ/dpQ)         |
| :---------------------- | :------------------ | :------------------ | :------------------------ |
| **传感器架构**          | 1:1:1 (全像素三层)  | 1:1:1 (全像素三层)  | **1:1:4 (亮度/色度分离)** |
| **核心算法**            | 色彩分离 (3x3 矩阵) | 色彩分离 (3x3 矩阵) | **亮度融合 & 色度外推**   |
| **图像压缩 (`IMAG`)**   | Huffman             | TRUE                | TRUE (Quattro 布局)       |
| **元数据加密 (`CAMF`)** | Type 2 (流密码)     | Type 4 (霍夫曼)     | Type 5 (霍夫曼)           |

### 2.3. Quattro 系列的处理陷阱

- **固件 Bug**: 某些相机的固件会写入错误的元数据（如黑电平区域坐标），解码器必须硬编码进行规避。
- **数据污染**: Quattro 传感器在成像区域嵌入了相位检测 AF 像素，必须通过坏点过滤算法剔除。
- **数据“半熟”**: Quattro 的 X3F 文件可能已经应用了部分校正（如空间增益），解码器需要避免重复应用。
- **DNG 工作流的妥协**: 相机直出的 DNG 是 12-bit 的“半熟”格式，已完成亮度融合，丢失了 2-bit 色深，且文件体积庞大。

## 3. 核心处理技术详解

`x3f-go` 项目为了获得高质量的输出，实现了一系列精确的算法。

### 3.1. 色彩校正与白平衡 (为何不偏色)

Foveon 传感器直出偏色的根本原因是其原生色域与标准色域不匹配。`x3f-extract` 通过以下精确步骤解决此问题：

1.  **精确的色彩矩阵转换链**:

    - **路径**: `传感器原生 RAW → XYZ(D65) → 目标色彩空间(sRGB/Adobe RGB)`
    - **矩阵来源**: `RAW → XYZ` 的矩阵来自相机 `CAMF` 元数据，这是 Sigma 针对每个型号精心校准的。`XYZ → 目标空间` 的矩阵则使用国际标准。
    - **中间标准**: 使用 XYZ 作为色彩无关的参考系，避免直接转换造成的色域映射问题。

2.  **白平衡增益的正确应用**:

    - 从 `CAMF` 读取的白平衡增益，不仅包含色温补偿，还综合了多重补偿：
      - **传感器校准增益 (`SensorAdjustmentGainFact`)**: 补偿传感器个体差异。
      - **温度增益 (`TempGainFact`)**: 补偿温度漂移。
      - **光圈增益 (`FNumberGainFact`)**: 补偿光圈影响。

3.  **黑电平和白电平的准确处理**:

    - 从多个屏蔽区域（上下左右）采样黑电平，并计算加权平均值。
    - 对每个颜色通道独立处理黑电平，避免暗部偏色。
    - 归一化时，每个通道使用独立的黑电平和缩放因子，避免通道间串扰。

4.  **空间增益校正 (Spatial Gain)**:
    - 应用位置相关的色彩增益图 (`GainMap`)，解决镜头暗角和传感器响应不均导致的边缘偏色问题。

### 3.2. AgX 色调映射流程

AgX 是一种旨在模拟胶片响应、提供优美高光过渡和色彩表现的色调映射算法。

- **整体流程**:

  ```
  RAW数据
    ↓
  [1] RAW解码和预处理 (得到 RAW Linear)
    ↓
  [2] 归一化 ([0.0-1.0])
    ↓
  [3] 色彩空间转换 (→ sRGB Linear)
    ↓
  [4] AgX Tone Mapping (核心步骤)
    ↓
  [5] Gamma校正 (→ sRGB Gamma)
    ↓
  [6] JPEG输出 ([0-255])
  ```

- **AgX Tone Mapping 详细步骤**:

  1.  **sRGB → E-Gamut**: 使用矩阵将 sRGB 线性数据转换到更宽的 FilmLight E-Gamut 色域，以保留更多色彩信息。
  2.  **Log2 编码**: 将线性的 E-Gamut 数据转换为对数空间，以压缩 HDR 动态范围并模拟人眼感知。
  3.  **3D LUT 查找**: 在一个 57×57×57 的 3D 查找表 (LUT) 中，使用三线性插值查找最终的颜色值。这是 AgX 的核心，可以同时处理亮度和色彩的复杂非线性变换。
  4.  **Rec.1886 → Linear**: 移除 LUT 输出自带的 Gamma 2.4 编码，转回线性空间，以便后续统一进行 Gamma 校正。

- **算法对比**:

| 算法   | 复杂度 | 核心原理                | 视觉特点                 |
| :----- | :----- | :---------------------- | :----------------------- |
| ACES   | 简单   | 有理多项式曲线          | 电影工业标准，标准化     |
| Filmic | 中等   | S 型曲线（Uncharted 2） | 模拟胶片，高光过渡柔和   |
| AgX    | 复杂   | E-Gamut + Log + 3D LUT  | 最电影化，细节保留最丰富 |

### 3.3. 四点双线性插值 (Merrill Spatial Gain)

对于 Merrill 系列相机，为了在不同光圈和对焦距离的 `Spatial Gain` 数据集之间插值，项目实现了四点双线性插值算法。

- **算法原理**:
  1.  **坐标系统**: 使用 `1 / 光圈值` 作为 X 轴，使用通过焦距和对焦距离计算的 `镜头位置` 作为 Y 轴。
  2.  **四象限选择**: 以目标拍摄参数为原点，在四个象限中分别找到距离最近的可用 `Spatial Gain` 数据块。
  3.  **权重计算**: 根据目标点与四个选定数据点在 X 和 Y 轴上的相对距离，分别计算 X 和 Y 方向的权重，然后相乘得到最终权重。
  4.  **数据插值**: 对每个像素位置的增益值，使用最终权重进行加权平均，得到插值后的 `GainMap`。

## 4. DNG 输出实现细节

### 4.1. Linear DNG 与色彩矩阵

`x3f-go` 生成的是 **Linear DNG**，它存储的是已经过处理的线性 RGB 数据，具有良好的兼容性。为了确保色彩正确，DNG 文件中必须精确设置以下色彩矩阵标签：

- **`ColorMatrix1`**: 固定的 `XYZ_to_sRGB` 标准矩阵的逆矩阵。DNG 的色彩转换流程是 `CameraRGB --[inverse(ColorMatrix1)]--> XYZ`。由于 X3F 的色彩校正已将图像转换到类 sRGB 空间，因此这里使用标准 sRGB 相关的矩阵。
- **`ForwardMatrix1`**: 相机特定的前向矩阵，计算公式为 `D65_to_D50_Adapter × sRGB_to_XYZ × ColorCorrections_From_CAMF`。它直接将相机校准后的 RGB 转换到 D50 光源下的 XYZ 空间。
- **`CameraCalibration1`**: 一个对角矩阵，包含归一化的白平衡增益倒数，用于抵消白平衡的影响。
- **`AsShotNeutral`**: 拍摄时的白平衡参数，值为归一化的白平衡增益倒数。

### 4.2. 多 Camera Profile 支持

为了在 Lightroom 等软件中提供多种渲染风格，`x3f-go` 在生成的 DNG 文件中嵌入了 6 个不同的 Camera Profile。

- **存储结构**:

  - 第一个 Profile ("Default") 的信息直接写入主 IFD (IFD0)。
  - 其余 5 个 Profile 以 DCP (DNG Camera Profile) 格式单独生成，并由 `ExtraCameraProfiles` 标签指向它们的偏移量。
  - DCP 格式是一个独立的、使用 Big Endian 字节序的 TIFF 结构，并以 "MMCR" 魔法字节开头。

- **定义的 6 个 Profiles**:
  1.  **Default**: 使用相机 `CAMF` 中的 `ColorCorrections` 矩阵，提供最接近官方的色彩。
  2.  **Grayscale**: 标准灰度转换。
  3.  **Grayscale (red filter)**: 模拟红色滤镜的灰度效果。
  4.  **Grayscale (blue filter)**: 模拟蓝色滤镜的灰度效果。
  5.  **Unconverted**: 不进行色彩转换，使用标准 sRGB 矩阵。
  6.  **Linear sRGB**: 线性 sRGB 色彩空间。

这些 Profile 允许用户在后期处理时，根据需求选择不同的色彩渲染起点。
